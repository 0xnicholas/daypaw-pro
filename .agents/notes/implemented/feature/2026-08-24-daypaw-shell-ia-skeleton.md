# Agent Note: daypaw shell IA skeleton — the ui-inbox workbench columns

Status: implemented

English | [中文](2026-08-24-daypaw-shell-ia-skeleton.zh.md)

## Problem

Spec 05 §3 rules the product shell's IA: a three-column inbox workbench (navigation / workspace / details) with presentation-layer vocabulary only. The [product-shell scaffold](../architecture/2026-08-23-daypaw-product-shell-scaffold.md) deliberately kept the complete upstream browser roster as placeholders so the composition boots; turning that roster into the daypaw IA (issue #55) had to answer three questions without breaking the dormant placeholder ecosystem: how the fork navigation replaces ui-sidebar when ui-workspace and ui-settings-general still register into ui-sidebar-declared seats, whether ui-conversation's middle/right occupants must be removed too, and how one selection state is shared when the three column slots live in three different scopes (root / session-maybe / session).

## Decision

A new client UI plugin package `packages/daypaw/ui-inbox` (`@daypaw/ui-inbox`, private, 0.0.0), shaped on upstream `packages/client/ui-sidebar`, makes three registrations in one `apply`:

- **`InboxNav` into `'sidebar'`** (root scope) — the ui-sidebar roster row is *removed* from `@daypaw/web-app`'s `cordis.patch.yml` (with its `package.json` dependency), not shadowed: ui-sidebar is in the spec §4 wholesale-rewrite cluster, and the dependents registering into its declared seats (`sidebar.workspaces`, `sidebar.settings`) use `ctx.slots.inject`, so with the declaration gone they pend silently with no load error. The nav renders the wordmark, the full-width primary 「+ 新任务」 button opening a minimal closable dialog stub (component-local open state; agent-selection content is the agent-catalog ticket's), the three groups 等待你确认/进行中/已完成 with placeholder-zero count slots, and the Agents/设置 secondary nav; collapsed it renders the contract-required 56px control rail (sidebar toggle + new-task icon button).
- **`WorkspaceSwitch` into `'conversation'` and `TaskDetail` into `'details'` at priority -1** — ui-conversation's roster row stays: its 11 declared seats, `useInput` standard kit, and `conversation` service serve the dormant placeholder ecosystem, so the fork occupants *shadow* the upstream priority-0 occupants (lowest live priority renders; a same-priority second registration throws). The middle column switches by selection between the group's empty-state task container and the Agents/设置 placeholder pages; the right column hosts the selected-task detail container (filled by the [task-progress board](2026-08-26-daypaw-task-progress.md)).
- **Selection crosses scopes through the inject `hooks` compartment** — a store handle cannot mount under two scopes (the registry throws), so one apply-closure `InboxSelectionController` holds a bare `SnapshotStore<InboxSelection>` (`{ kind: 'group', group } | { kind: 'agents' } | { kind: 'settings' }`, default the 进行中 group), surfaced identically in each register call's `hooks: { selection }`; the renderer binds it as each component's `useSelection` hook, per the [slot system standard](../architecture/2026-07-22-slot-type-chain-implementation.md). Registration order is safe without `ctx.slots.inject`: the cordis fiber inject waits on the `layout` service, which ui-layout provides in the same effect that declares the four slots (the ui-sidebar precedent; the declaration-injection mechanism of the [slot-declaration note](../architecture/2026-08-05-slot-declaration-injection.md) stays for order-independent contributors like the pended ui-workspace).
- **Locale and styling follow roster convention** — the plugin owns the `inbox` namespace via `LocaleNamespaceMap` merging and registers zh plus en (the typed register requires every shipped locale; the lookup chain falls back to zh, the product copy). Styles are CSS Modules over `--dsw-alias-*` semantic tokens and the `--dp-space-*` density scale (the [brand theme layer](2026-08-27-daypaw-shell-brand-theme.md) now supplies both; the skeleton shipped with hand-set medium-low spacing, later tokenized by the same ticket).

Tests follow the sanctioned zero-machinery path of the [GUI testing system](../process/2026-07-20-gui-testing-system.md): component specs render with realistic props (a real controller plus `bindSnapshotSelector` for the hooks compartment, never-called stubs for the framework seats), an apply spec over a real `SlotRegistry` + `LocaleRuntime` pins occupancy, the -1 shadowing, the shared selection source, and teardown, and a `toMatchSnapshot` pins the expanded skeleton. Package src sits at per-file 100% coverage. New core touches (tsconfig.client.json reference + css-modules include, knip workspace block) are registered in [CORE_TOUCHES.md](../../../../docs/fork/CORE_TOUCHES.md).

## Alternatives considered

- **Remove the ui-conversation roster row too** — rejected: its declared seats and services are the dormant ecosystem's composition surface (ui-tool, ui-deliverables, and friends register into them), so removal has a large blast radius for zero skeleton benefit; priority -1 shadowing replaces exactly the two visible cells while the row's slot declarations stay live.
- **Shadow ui-sidebar at priority -1 instead of removing its row** — rejected: keeping the upstream shell mounted would keep its declared seats alive for ui-workspace/ui-settings-general, but those registrations are themselves placeholders scheduled for wholesale rewrite, and an invisible upstream shell would still own the nav's presentation contract; removal is the rewrite cluster's endgame and the pending dependents fail silently by design.
- **One shared store handle registered under all three slots** — impossible, not merely rejected: the slot registry throws when one handle mounts under two scopes, and three per-scope handles would fork the selection state the workbench exists to share; the inject `hooks` compartment is the standard's sanctioned channel for a registrant-private reactive fact.
- **Wait on the slot declarations with `ctx.slots.inject`** — rejected for this package: the fiber inject on the `layout` service already orders this plugin after ui-layout's declaring effect (ui-sidebar does the same), and `slots.inject` exists for contributors whose activation order is independent of the declaring entry, which a same-composition column occupant is not.

## Consequences

The daypaw web surface renders the inbox-workbench skeleton end to end — left nav with groups/count slots and secondary nav, middle column switching with selection, right detail placeholder — while the upstream developer-facing conversation surface is invisible but still mounted underneath. Every later board ticket (counts/entries wiring, new-task dialog content, Agents/设置 pages, task detail) extends this package's components or replaces its placeholders without touching the frame. Cost: the shadowed ui-conversation occupants still load and their seats still accept registrations, so the composition carries the dormant tree until the board epics remove it; and the fork's three-column copy now drifts independently of upstream sidebar/conversation development.
