# Agent Note: shell-started runs, shell side — dialog, board, preset retirement

Status: implemented

English | [中文](2026-08-30-shell-started-runs-shell-side.zh.md)

## Problem

The [host side](2026-08-30-shell-started-runs-host-side.md) gave the shell host a definition registry and `durable/startRun`, but the browser still started tasks the old way: the new-task dialog picked a dsh preset and ran `agentPresets.list → sessions.create → prompt`, the board's conversation opening still keyed off that create path, and the first-run banner named the default preset. Ticket #67 welds the shell UI to the engine: the dialog reads `durable/listDefinitions` and starts runs, the started run lists and opens its conversation (sessionId ≡ runId), and preset surfaces retire to the compatibility layer.

## Decision

- **The dialog's roster is the engine registry** (one roster, ADR 0012). `NewTaskStore` now loads agent definitions over the connection's generic RPC channel (`new-task-api.ts`: `durable/listDefinitions` filtered to `kind: 'agent'`, payload validated at the wire boundary — the ui-agents catalog precedent). Rows carry `name@version` as the select value (the submit pins the exact version, so multi-version coexistence never silently picks), the label is the declared display title falling back to the technical name, and the first row is preselected — registration order IS the order `loadAgentFiles` guarantees.
- **The input surface follows `inputKind`** (ruling #65 §7): `text` renders the free-text area, `json` and `null` (engine-native definitions without a wire face) render a JSON area with inline syntax validation — a malformed draft keeps submit disabled and shows the localized JSON error; the definition's own zod contract still validates host-side. For the `z.object({ task: z.string() })` starter shape the dialog sends the bare string and the **wire face owns the wrap**: `wireFace` compiles `parseInput` to accept the free-text string and wrap it before the zod parse, so both starter shapes hand the same wire payload and `inputKind` stays purely presentational. The ledger row's `input_json` proves the coercion (pinned in sdk `agents-dir.spec.ts`).
- **Submit mints one run id and keeps it across failures.** `pendingRunId` is minted lazily at the first submit attempt and survives failed submits (inline failure, draft kept); `durable/startRun`'s start-or-attach makes the retry land on the same run instead of double-creating. On success the id is cleared so the next task mints fresh. After the start answers, the store waits for the run's **session twin** to reach the sessions-list projection (`whenListed`, bounded at `TWIN_WAIT_MS` with an injectable timer — a run that failed before creating its session retires the submit inline instead of parking the dialog forever, and the kept id makes the retry attach): the engine creates the session on first drive and emits `api-session/added`, and `sessions.open` fails loud on unlisted ids — so `openTask` fires only when the conversation can actually resolve. A failed roster load retries on the next dialog open (the effect reloads from `error`, not just `idle`). InboxNav's `openTask` also kicks a board refetch (a new `refreshBoard` inject) so the run lists without waiting the 2s poll.
- **Preset retirement is a patch disable plus a name-source switch.** The daypaw patch disables `ui-agent-preset` (disable, not delete — the shared-base precedent): its before-the-fact surfaces (the General default-preset row, the new-session chip, the roster management section) would promise a choice the product no longer offers, while sessions already composed with a preset keep their mounted composition and stay openable. The first-run banner's name source switches from the default preset to the roster's first agent (`durable/listDefinitions` over the connection's RPC channel — the seeded starter's display title, generic name on an empty roster).
- **The fixture mirrors the engine's start semantics** so every client lane stays keyless: `durable/startRun` resolves the registry identity (exact version, or the name's unique entry — ambiguity rejects naming the candidates), coerces the starter text shape, answers an existing run id as attach, and otherwise appends a running row, creates the sessionId≡runId twin, and drives the first turn through the internal prompt path — the first user message is the input's JSON serialization (the ADR 0010 behavior the conversation actually shows).

## Alternatives considered

- **Sending `{ task: text }` from the dialog for task-shaped definitions** — needs the shape exposed in `DefinitionView` (engine surface growth) and splits shape knowledge between wire face and dialog. The wrap belongs to the compiled face, which already knows the contract.
- **A `null`-inputKind row in the dialog roster marked "advanced"** — engine-native registrations never occur in the daypaw composition (SDK bind always stamps a wire face); the JSON box covers the shape honestly without new copy.
- **Keeping the banner on the preset name** — presets are the compatibility layer now; naming the first-run card after a roster the user cannot pick from would be false.
- **Deleting `ui-agent-preset` from the patch rows** — deleting would let the row silently reappear on a base reorder; the disable marker with the ruling comment is the auditable retirement.

## Consequences

- A shell-started task is a durable run end to end: dialog → `durable/startRun` → twin wait → conversation; the board lists the run (kick + poll) and its row opens the same session; SIGKILL revival rides the engine's boot scan with no shell-side state.
- The conversation's first user row reads as the input's JSON text (`{"task":"write a poem"}`) — ADR 0010's logged-first-message contract, mirrored by the fixture's echo. A human-readable first message for starter shapes would be an engine/SDK decision, not a shell projection; recorded here as the deferred item.
- The #60 dual-roster Known Limitation retires (ui-agents README updated); preset sessions remain visible and openable (the sessions-list side of the board projection is untouched).
- Old preset-less suites changed shape: ui-tasks' fake and specs now program `durable/*` endpoints; ui-settings' card specs program the roster RPC; the assembled goldens (dialog options, conversation shape, catalog grid) record the definition-roster world.

The fixture spec pins start-or-attach, coercion, twin listing, id minting, and both rejection messages. The assembled lane refreshes `inbox-conversation` (dialog → run → conversation → board row → back to conversation) and `agents-catalog` goldens; per-file coverage of every touched non-exempt source file is 100%.
