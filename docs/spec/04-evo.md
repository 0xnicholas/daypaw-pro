# 第 4 章：EVO（骨架输入）

> 状态：**骨架输入**——结构已定，内容待 spec 撰写期填充。决策依据 [ADR 0005](../adr/0005-evo-loop-mechanics.md)；数据契约见 ADR 0004 §6；AIP Evolve 事实底座 `docs/research/aip-evolve.md`（发布机制无公开文档，标注了设计自由区）。

## 1. 优化对象与变体模型

定义级变体 + 类型化算子三维度（模型路由 / prompt 段 / 工具面子集，ADR 0005 §1）。算子的类型定义、组合行 diff/merge 语义、变体命名与注册表接入：待写（与第 2 章 §3 版本语义交叉引用）。架构级第四维（消除不必要 LLM 调用）：雾区，待结构化数据源。

## 2. 评估集

来源三层：真实提取（ledger/session log，人反馈 run 优先）+ 人策种子 + 合成扩量（标记隔离）；dataset = 关联层概念实例（ADR 0005 §2）。提取管线（run → 输入→期望输出对）、策展工具面：待写。漂移四层防线（版本化 / 定期补充 / 合成隔离 / 发布后监控）机制细节：待写。

## 3. 循环机制

两段式生成（规则枚举离散维度 + LLM 重写语言维度）、按需触发、双预算上限（迭代 + 成本）、本体 = `defineWorkflow`（生成/评估/剪枝/提案 step + 人审 gate，ADR 0005 §3/§6/§7）。优化 run 的 workflow 代码骨架、配置面 schema（目标定义 / 算子 allowlist / 验证策略 / 数据集版本 / 预算）：待写。

## 4. 判定与晋升

双门判据 + 分层 judge（zod → rubric → 人工抽检），严格度按维度配置（ADR 0005 §4）。ε 与容差默认值、抽检采样率、rubric 题板形态、judge 的成本记账（judge 自身也是 LLM 调用）：待写。

## 5. 发布与 provenance

代码提案通道：类型化 diff → 人审 → 代码新版本（可代开 PR）；git 即版本史、回滚 = revert（ADR 0005 §5）。提案文档结构、EVO 开 PR 的操作面（自用场景自动化到什么程度）：待写。

## 6. 数据模型
