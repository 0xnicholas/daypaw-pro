# ADR 0013: 产品定位重审——双模式分层

- **状态**：已接受（2026-09-02，[daypaw 产品定位重审：为谁、露什么面](https://github.com/0xnicholas/daypaw-pro/issues/95)）
- **前置**：spec 05 §1 初裁（map #35——业务用户优先）；ADR 0009（支柱边界）；ADR 0011（自跑交付）；[map #77](https://github.com/0xnicholas/daypaw-pro/issues/77) 前端架构复盘（定位重审的触发语境）
- **事实底座**：[使用证据盘点](https://github.com/0xnicholas/daypaw-pro/issues/96)（壳落地 ~10 天共 3 run、零追问/审批/轻对话；owner 日常对话在 daypaw 之外；仓库零外部客户信号）；[dsh 可挂面清单](https://github.com/0xnicholas/daypaw-pro/issues/97)（「未挂载」大半不成立，真轴是能力底座——工具行全禁使五面饿死、审批面无触发源）；[功能走查](https://github.com/0xnicholas/daypaw-pro/issues/84) 缺口②（轻对话入口被 IA 收起）

## 决策

### 1. 定位调整为双模式分层

daypaw = 「持久执行 + agent 的日常驾驶舱」。技术用户（自用 + 技术客户）使用全能力面（专业视图、工具套件开启）；业务语言壳为**默认皮肤与对外交付形态**。先成为 owner 自己的日常驻留地，业务面向客户生长。客户构成事实：混合/过渡（技术型为主、向业务侧长）。

### 2. IA = 单壳分层，无全局模式开关

业务壳为默认；专业面在视图内按需展开——trajectory 作会话/任务检查器 tab（上游 view-ring 的一席）、verbatim 工具卡即专业展开层、命令面板随工具启用自然变丰。轻对话（不经引擎 run 的普通会话）入口接回（#102），任务与对话成为并列入口。

### 3. 能力底座全开，审批护栏不动

模型侧工具行（bash/fs/web/subagent/jobs/goal/workflow…）整组启用（#103）；#46 保守默认「敏感操作必审批」维持，作为工具开放后的唯一防线，须实测审批闭环（走查缺口③根治——工具全禁时审批面无触发源、长期空转）。

### 4. 附属再裁

- **#36「重写 ui-user-questions/ui-deliverables」取消**：两包维持原样挂载（形态中性），与现实的偏差就此对齐；业务皮肤化挂账待真实客户反馈。
- **语言化窄面挂账、使用驱动**：工具卡业务原子视图（`tool.call.toolview` 槽逐工具做）、设置高级区残差（`settings.section` 槽放开 + 本地配置动作）不预做。
- **ADR 0009 边界不动**：Manager 仍为远期独立子项目；双模式的专业视图只**消费现有上游面**，不新建观测产品。

否决：维持业务用户优先（使用证据不支持——业务用户未出现、自用也未形成习惯）；重定义为纯开发者工具（客户构成混合，业务语言壳的投资是对外交付形态，保留）。

## 后果

- spec 05 §1/§3/§4/§6/§8 按本 ADR 修订（定位、IA 增量、复用边界两行翻案、能力底座、雾区）。
- 执行票：#102（轻对话入口）、#103（工具套件启用 + 审批复测）、#104（ui-attachment/ui-reference roster）、#105（trajectory 高级视图露出）。
- map #35 的 #39 IA 骨架、#40 词汇映射、#46 权限模型维持不变；「一切对话皆任务」立场废止。
