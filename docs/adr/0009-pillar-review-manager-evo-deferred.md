# ADR 0009: 需求重审——Manager 与 EVO 降级为远期独立子项目

- **状态**：已接受（2026-08-19，[需求重审：四支柱性价比](https://github.com/0xnicholas/daypaw-pro/issues/22)）
- **前置**：ADR 0002（引擎语义）、ADR 0003（编程模型）、ADR 0004（Manager 范围与控制面）、ADR 0005（EVO 循环机制）、ADR 0008（落地顺序与 walking skeleton）
- **事实底座**：seam 清点 v2（`docs/research/dsh-seam-inventory-v2.md`，分支 `research/seam-inventory-v2`）——四支柱各自的 upstream 替代物均为**无**（执行级 durability 仍全留白；无用户代码优先编程模型；无完整 Manager；无优化环）；但单进程观测/检索/控制面显著加密，支柱③自建面收窄为「跨 run/跨进程聚合 + durable run 视图 + 控制命令」三件事。

## 决策

### 1. 四支柱重审为「两支柱 + 两个远期独立子项目」

- **① Durable Execution、② Agent Engine + SDK：保留**，立即推进。批次 C（walking skeleton）范围不变——走骨只含①，开工判据完好。
- **③ Agent Manager：降级为远期独立子项目**，后期单独立项。理由：收窄后的自建面三件事，其输入（durable run 语料、多进程跑 run 的使用形态）在①落地前不存在；自用单机下不为它排独立里程碑。①调试期需要的 run 视图用临时工具（CLI/SQL 查询）应急，不预建 Manager 面。
- **④ EVO：降级为远期独立子项目**。理由：四支柱中面最大、回报最投机——回报前提是大量重复运行、值得自动优化的 agent 负载；自用下手动迭代 prompt/模型的成本低得多。等①②跑出真实遥测语料与重复负载后再评估毕业。

### 2. 语料处置：方向文档化，不归档

- spec 03/04 骨架、ADR 0004/0005 保留为各子项目的**方向文档**，状态行加降级标注；不归档、不删除——两章的设计结论在子项目立项时仍是起点。
- ②的定义注册表与版本化设计正当性自立（`defineAgent` 的组合与版本化是②自身的需要），不再以「EVO 前提」作为迫近理由。
- 原 map（[daypaw-pro Agent Stack 架构图](https://github.com/0xnicholas/daypaw-pro/issues/1)）的 EVO 第四维雾区（架构级优化数据源）作废。

### 3. 后续语料的 frame

spec 00-overview（ADR 0008 批次 D）按「两支柱 + 两个远期子项目」frame 撰写；支柱③④的关联层、评估集等地界问题移至各自子项目立项时重开，现役设计语料（spec 01/02、ADR 0006/0007/0008）不因降级改动语义。

否决：整体砍掉③④并归档语料（方向价值仍真，语料是已付的设计成本，归档丢掉复用起点）；为③④保留支柱排期（自用性价比不成立，且③的输入语料不存在）。

## 后果

- 「四支柱」作为历史/集合名词保留（fork 叙事来源），现役 frame 是两支柱 + 两个远期子项目。
- 一致性走查票新增「ADR 0009 与旧 ADR 消歧」输入；清晰度裁决票的 spec 00 形状输入更新。
- 自用约束（单机、本地、无多租户、无公开 API 稳定性承诺）不变。
